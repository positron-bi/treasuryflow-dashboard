# TreasuryFlow Dashboard

مسیر کد فعال این است: `%USERPROFILE%\Desktop\خرانه پیشبینی\treasuryflow-dashboard`.

اپ ویندوزی به‌روزرسانی خودکار گزارش جریان نقد پوزیترون. برنامه برای استقرار در
`X:\Accounting\report flow` طراحی شده و همه ورودی‌ها و خروجی‌های عملیاتی را در همان پوشه نگه می‌دارد.

## استفاده روزانه

1. در پوشه شبکه روی میانبر `TreasuryFlow` بزنید. این میانبر `TreasuryFlow.vbs` را اجرا می‌کند و نسخه اصلی را در کش محلی کاربر همگام می‌سازد تا اجرای برنامه از روی شبکه معطل اسکن امنیتی فایل اجرایی نشود.
2. هر فایل را با دکمه مستقل خودش انتخاب کنید: «گزارش روزانه خزانه»، «ورودی‌های دستی» یا «گزارش تسهیلات».
3. دکمه سبز «بارگذاری فایل‌های انتخاب‌شده» را بزنید. فایل انتخاب‌شده در پوشه برنامه ذخیره و داشبورد ساخته می‌شود.
4. برنامه همچنین هر ۵ ثانیه تغییر فایل‌های داخل پوشه را تشخیص می‌دهد و `index.html` و گزارش تاریخ‌دار را می‌سازد.

اگر `TREASURYFLOW_PUBLISH_REPO` تنظیم شده باشد، همان `index.html` رمزگذاری‌شده پس از هر ساخت موفق به GitHub Pages نیز push می‌شود. خطای اینترنت یا Git مانع ساخت نسخه محلی نمی‌شود و در رویدادهای برنامه ثبت خواهد شد.

در استقرار اصلی، Task Scheduler هر یک دقیقه `TreasuryFlow.vbs /auto` را بدون پنجره اجرا می‌کند. بنابراین برای تشخیص و انتشار فایل جدید لازم نیست رابط برنامه باز بماند؛ میانبر فقط برای انتخاب دستی فایل‌هاست.

راه‌انداز فایل کاربران را از Desktop مدیر با `.dashboard_access\dashboard_users.xlsx` مخفی در پوشه شبکه همگام می‌کند. سیستم‌های دیگر در نبود فایل محلی از نسخه مشترک استفاده می‌کنند و فقط سیستمی که checkout پروژه را دارد انتشار GitHub را انجام می‌دهد.

هر دو خروجی HTML با کاربران Active ستون `Treasury` در
`%USERPROFILE%\Desktop\DashboardAccess\dashboard_users.xlsx` رمزگذاری می‌شوند. تغییر این فایل نیز مانند تغییر فایل‌های گزارش، ساخت مجدد داشبورد را فعال می‌کند. مسیر فایل دسترسی را می‌توان با متغیر `TREASURYFLOW_ACCESS_FILE` تغییر داد.

فایل‌های شناخته‌شده:

- `Treasury Daily Report - 1405-05-28.xlsx` یا `daily.xlsx`: گزارش روزانه خزانه، با رمز پیش‌فرض `1123`.
- `Manual_Inputs.xlsx`: ورودی‌های دستی، Policy، Capex، Credit Lines و Sales Budget.
- `گزارش تسهیلات.xlsx`: تاریخچه کامل تسهیلات برای محاسبه دقیق چرخه‌ها.

گزارش روزانه اجباری است. دو فایل دیگر اختیاری‌اند، اما نبودشان در داشبورد با هشدار نشان داده می‌شود.

## رفتار به‌روزرسانی

- تغییر بر اساس نام، اندازه، زمان و SHA-256 محتوای هر سه فایل تشخیص داده می‌شود.
- پیش از پردازش، کامل‌شدن کپی فایل کنترل می‌شود.
- فایل Excel منبع هرگز بازنویسی نمی‌شود؛ رمزگشایی گزارش روزانه فقط در حافظه انجام می‌شود.
- خروجی ابتدا با نام موقت ساخته و سپس جایگزین می‌شود تا کاربران فایل نیمه‌کاره نبینند.
- اسنپ‌شات‌های تاریخ‌دار در `snapshots` باقی می‌مانند تا تب «تغییرات نسبت به گزارش قبل» کار کند.

## اجرای نسخه کد

```powershell
python -m pip install -r requirements.txt
python app.pyw
```

ساخت فایل اجرایی:

```powershell
.\build_app.ps1
```

برای اجرای محلی، دو فایل `dist\TreasuryFlow.exe` و `dist\TreasuryFlow.runtime.exe` باید کنار هم باشند. در استقرار شبکه، نسخه اجرایی با نام `TreasuryFlow.runtime.v2.exe` همراه `launcher\TreasuryFlow.vbs` و یک میانبر ویندوز استفاده می‌شود.

## کنترل کیفیت

```powershell
python -m unittest discover -s tests -v
```

پایپ‌لاین اصلی در `pipeline/build_forecast.py` و قالب ۱۸ تب داشبورد در `pipeline/assets` است.

## امنیت داده

فایل‌های Excel، JSON، HTML، اسنپ‌شات و لاگ در `.gitignore` قرار دارند و نباید در GitHub commit شوند.
خود `index.html` شامل داده‌های مالیِ قابل‌خواندن است؛ دسترسی پوشه شبکه باید فقط برای افراد مجاز باشد.
